# Память проекта NetShift

Обновлено: 2026-10-13. Используй эти сведения как контекст проекта и актуализируй файл при крупных изменениях. Этот `AGENTS.md` хранится в `.codex/AGENTS.md` и отслеживается Git.

## Проект

- Публичный репозиторий: https://github.com/rkfsociety/NetShift
- Основная ветка: `main`. Последний опубликованный релиз: `v0.3.059`. Версию текущей разработки и занятость следующего тега проверять по `NetShift.App.csproj` и опубликованным тегам.
- Приложение: WPF + Windows Forms tray на C#, .NET 10, проект `src/NetShift.App`.
- Системная DNS-служба: `src/NetShift.DnsService`, версия payload `1.0.0`.
- Пользователь предпочитает общение на русском.

## DNS

- Пресеты определены в `src/NetShift.App/Models/DnsProvider.cs`: Cloudflare, Google Public DNS, Quad9, AdGuard DNS, Comss.one, Xbox DNS, DNS-AI и «Свой DNS».
- DNS-AI (`DnsAiProviderService`) загружает адреса и DoH-шаблон с https://dns-ai.ru/#setup при старте; есть встроенные резервные значения.
- Comss.one: Windows preset — IPv4 `83.220.169.155, 212.109.195.93`, IPv6 отсутствует в опубликованном списке, DoH `https://dns.comss.one/dns-query`. Адрес `195.133.25.16` на странице Comss приведён для маршрутизаторов; Windows инструкция использует стандартные IP + DoH-шаблон.
- Xbox DNS preset — IPv4 `111.88.96.54, 111.88.96.55`, IPv6 `2a00:ab00:1233:26::50, 2a00:ab00:1233:26::51`, DoH `https://xbox-dns.ru/dns-query`. При проверке 2026-10-12 сайт Xbox DNS сообщал о временной недоступности; перепроверять статус по официальному сайту перед рекомендациями.
- NetShift применяет системный DoH средствами Windows DNS Client. DoT и DoQ в приложении не реализованы.
- DNS-профиль хранится в Windows, привязан к GUID интерфейса и переживает закрытие/обновление приложения. Не отключать DNS при обновлении NetShift.

## Службы, запуск и трей

- `NetShiftDns` устанавливается как Windows-служба LocalSystem с автоматическим запуском и работает независимо от GUI. Профиль DNS восстанавливается после перезагрузки.
- Релизный EXE содержит payload DNS-службы; при первом запуске приложение устанавливается в `%LOCALAPPDATA%\Programs\NetShift`, создаёт ярлыки Desktop и Start Menu на установленный EXE и запрашивает UAC для системной службы.
- Автозапуск GUI — пользовательский переключатель; служба должна запускаться независимо от него.
- Закрытие окна скрывает приложение в трей. «Выход» закрывает GUI, но не сбрасывает DNS и не останавливает zapret.

## Flowseal / zapret

- NetShift скачивает последний официальный релиз https://github.com/Flowseal/zapret-discord-youtube и управляет его стратегиями/службой через интерфейс.
- Сам upstream zapret в исходники NetShift не включён; проверять лицензию и состав загружаемого upstream-релиза.
- Полный перебор `general*.bat` сортирует по естественному порядку и выполняет под UAC по одному официальному `.bat` на стратегию через `cmd.exe /c "путь к файлу"`. Для URL из `utils/targets.txt` запускаются три пробы `curl.exe -I` (HTTP/1.1, TLS 1.2, TLS 1.3); ping проверяется для всех URL- и PING-целей. Успех curl определяется кодом завершения процесса, HTTP status code не учитывается. Перебор проверяет все стратегии, затем выбирает максимальное число успешных curl-проб, при равенстве — число успешных ping; дальнейшее равенство разрешается первым вариантом в естественной сортировке. Тестовый `winws.exe` останавливается после каждой стратегии. В списке зелёные стратегии означают успех всех HTTP/TLS и ping проверок, жёлтые — частичный успех, красные — отсутствие успешных проб; список сортируется по этим статусам, затем непроверенные варианты. Рекомендация пульсирует, сохраняя фактический цвет статуса.
- Если служба zapret уже работает, NetShift проверяет только её стратегию и не прерывает службу. Для полного перебора служба должна быть остановлена; при работающем ручном `winws.exe` перебор отклоняется, чтобы не запускать стратегии параллельно.
- Ручной запуск выполняет официальный выбранный `general*.bat`, скрывает консоль точного процесса `winws.exe` из выбранной папки и проверяет, что процесс запустился. UI отдельно показывает состояние службы и ручной стратегии; закрытие/остановка скрипта обновляет этот статус.

## Релизы и обновления

- Workflow: `.github/workflows/release.yml`. Публикация тега `vMAJOR.MINOR.PATCH` собирает самоустанавливающийся `NetShift.exe`; единственный загружаемый asset релиза — этот EXE. Обновлятор скачивает его напрямую, сверяет размер и SHA-256 digest из GitHub API. GitHub также показывает автоматически созданные Source code ZIP и tar.gz — это не assets приложения.
- Workflow удаляет предыдущие GitHub releases и старые version tags, оставляя только текущие. Пользователь просил сохранять публичный репозиторий и только самый новый релиз.
- При каждом изменении приложения поднимать patch-версию синхронно в `<Version>` (`NetShift.App.csproj`) и fallback в `NetShiftUpdateService.CurrentVersion`, даже если push не запрошен.
- Patch-версия должна отображаться тремя цифрами (`0.3.007`, затем `0.3.008`). `CurrentVersion` извлекает номер из `AssemblyInformationalVersion`, сохраняя нули и отбрасывая SHA; сравнение обновлений использует числовой `Version`, поэтому `0.3.007` новее `0.3.6`.
- Тема UI должна оставаться тёмной; основная навигация слева, разделы DNS, zapret, Настройки и О программе используют общую оболочку с тёмной строкой заголовка и синими/голубыми акцентами.
- После изменения всегда создавать локальный commit. Push `main`, создание/отправка version tag и публикация релиза выполняются только по прямому запросу пользователя; без него остановиться после коммита.
- Перед каждым push актуализировать этот `AGENTS.md` по текущему состоянию проекта и проверить, что его сведения о версиях, релизах и поведении приложения не устарели.
- Если пользователь просит push/release, отправить `main`: workflow сам создаёт и отправляет тег `vMAJOR.MINOR.PATCH`, когда версия приложения новее существующих тегов. Дождаться GitHub Actions и проверить успешность workflow, assets и что остался один release/tag. Не отправлять тег вручную при обычном push в `main`.
- Не возвращать ZIP и отдельные checksum-файлы в assets без изменения updater и явного решения: текущий updater ожидает `NetShift.exe` и его digest из GitHub API.
- В v0.3.6 исправлена обработка CLIXML и кодировки в PowerShell worker для DNS-применения и восстановления службой.
- В версии `0.3.026` резервная копия Legacy DNS не перезаписывается при повторном включении; режим DNS DHCP/static сохраняется отдельно для IPv4 и IPv6.
- Остановка Legacy DoH proxy, административные операции и диагностика работают асинхронно; DoH-запросы ограничены 64 одновременными задачами и завершаются вместе с прокси.
- Установщик обновления проверяет копию EXE и сохраняет резервную версию до успешного старта новой; workflow релиза сериализован, пропускает теги старше версии в `main` и удаляет только более старые версии.
- `tests/NetShift.RegressionChecks` — Windows PowerShell проверки Legacy DNS и таймаута внешнего процесса; workflow запускает их перед сборкой релиза.
- Последний подтверждённый релиз: https://github.com/rkfsociety/NetShift/releases/tag/v0.3.059

## Сборка

Локальная сборка приложения:

```powershell
.\.tools\dotnet\dotnet.exe build .\src\NetShift.App\NetShift.App.csproj --configuration Release
```

Релизный workflow сначала публикует self-contained DNS-службу для win-x64, затем встраивает её в self-contained single-file приложение.
